# Introduction

Pac-Man Arcade Lab is a Pac-Man that plays like the 1980 arcade machine, and a workbench for
studying how it does that. This manual is for three kinds of readers:

- **Players**: how to play, the controls and the options. Start with
  [Playing](./02-playing.md).
- **The curious**: how the arcade game really works, rule by rule, with the source of each rule
  and where this game implements it. That is [The arcade rules](./03-arcade-rules.md), our own
  "Pac-Man Dossier".
- **Developers and tools**: how the game is built, tested and debugged, and how to drive it from
  scripts, tests or another program: [Architecture](./04-architecture.md) and the chapters after
  it.

The same files are in the repository under `docs/manual/`, so the manual reads on GitHub too.

## What this game is

- **Two modes.** Pac-Man, and Ms. Pac-Man (the same rules, her look and one maze of her own with
  two tunnels; its colors change between levels).
- **The arcade's mechanics, measured in the arcade's own units.** 8-pixel tiles, whole-pixel
  positions, one simulation step per arcade frame at 60.606 frames per second. Speeds, turns,
  ghost decisions, the ghost house and the level table follow _The Pac-Man Dossier_ by Jamey
  Pittman and other published analyses. Where no published source gives a value, the game uses
  an estimate and says so: see [Estimates and open questions](./03-arcade-rules.md#estimates-and-open-questions).
- **A deterministic simulation.** The same start and the same inputs always give the same game,
  frame for frame. That is what makes rewind, replays, share links and the golden replay tests
  possible.
- **Tools.** A Lab panel with a ghost AI explainer, practice tools (rewind, slow motion, routes,
  a death heatmap) and a Debug tab; a debug overlay; replays; an agent driver that scripts and
  inspects the game from the browser console or from tests.

## Quick start

Play: open the game ([online](https://g-t-georgiev.github.io/pacman/), or your own dev server), wait for **READY!**, and steer with the arrow keys (or W A S D). Eat every
dot to clear the level. Eat an energizer (the big flashing dot) and the ghosts turn blue: eat them
for 200, 400, 800 and 1,600 points.

Run it yourself (the project uses [Vite+](https://viteplus.dev/guide/), the `vp` command):

```bash
vp install           # dependencies
vp dev --port=3000   # the dev server: the debug overlay, agent driver and diagnostics are on
vp test              # every test, including the browser tests
```

See [Testing](./06-testing.md) for the rest of the commands.

## How this manual marks things

- A rule's **source** is named where it is given: "Dossier" means _The Pac-Man Dossier_, and
  "Table A.1" is its per-level table.
- **Estimate** marks a value no published source gives: chosen from play and video, and listed in
  the [open items](../OPEN_ITEMS.md) to confirm.
- File names like `src/game/GameEngine.ts` point to the code. In the game's page they show the
  path when you hover them.
