> _Understanding Pac-Man Ghost Behavior_ (Birch), and the Steam guide (a derivative of those two;

> branding more closely. For the presentation layer, use your own visuals, sounds and maze

Legend: **Impact** = how much a player would notice. **Effort** S < 1h, M = a few hours, L = a day+.

## Decisions (2026-11-08)

1. **Type safety vs. data.** Keep `strict: true`. Drop `noUncheckedIndexedAccess`. Mazes and level
   tables are trusted, predefined data. Bad data is fixed where it comes from and caught by
   data-validation tests, not guarded at every index. Two cases are real game rules, not
   validation, and each lives in one place: level lookups past the last table row clamp to that
   row, and tunnel coordinates outside the grid wrap through one `tileAt` accessor.
2. **Game modes.** Keep **Pac-Man** and **Ms. Pac-Man**. Remove Crazy Otto and Cookie Man and
   everything that only serves them (H7). The PDFs don't cover Ms. Pac-Man's own mechanics, so
   those parts can't be checked against a source.
3. **No MAME/ROM.** T10 is dropped. Golden replays are regression tests that check the game
   against itself. Expected values come from the Dossier tables.
4. **Coordinates.** The sim uses arcade 8-px tiles (`TILE_SIZE = 8`), and only the renderer
   scales ×2 (`RENDER_SCALE`, `RENDER_TILE_SIZE`).
5. **Input buffering stays** (`nextDir`). A held key behaves like a held joystick. The only
   difference is tap-and-release, where the arcade forgets the direction. A "clear on release"
   option can come later (Phase 5).
6. **Speed masks stay hand-authored bit patterns, not computed.** The format is two 16-bit masks
   per speed, `step1` and `step2`, indexed by `frame % 16` (MSB = frame 0). Each set bit is one
   arcade-pixel step, so a frame moves 0, 1 or 2 px. Every step runs the full single-pixel
   update (tile entry, decisions, wrap, collision). The tables are swappable data. Until a
   verified source turns up, the defaults use the Dossier scale (100% = 1.25 px/frame), so each
   5% is one set bit per 16 frames (80% = 16 bits, 100% = 20, 105% = 21). A test checks only
   the bit counts, not the arrangement.

## 0. Current state: what's already good

- The core shape is right: tile-based targeting, one-tile lookahead, UP > LEFT > DOWN > RIGHT
  tie-break, no voluntary reversal, forced reversal on mode change, tunnel slowdown zones, the
  no-up intersections, Pinky/Inky up-overflow behind a flag, Clyde's 8-tile rule, and
  tile-occupancy collision. The pass-through bug falls out of that last one naturally.
- Fixed-timestep loop, controller split, a PRNG module, an event bus, a rewind buffer, an
  in-game diagnostics console, and 55 passing tests (`vp test`).
- The frightened-time and flash-count tables match Table A.1. The 244-dot classic layout parses
  correctly (240 dots + 4 energizers).

The biggest problems: the speed model is off by a large constant factor. Ghost-house release
is timer-based instead of dot-counter-based. Several reversal and frightened details differ from
the Dossier. And the sim isn't deterministic enough yet to test any of this tightly.

## Sources added (2026-11-08)

Two Retro Game Mechanics Explained transcripts (ghost AI; frightened ghosts) and a Markdown copy of
the Dossier. They agree with the Dossier and Birch on everything below, and add the PRNG details.

- **Decisions happen on every tile entry**, not only near intersections (Dossier "Looking Ahead",
  RGME). On a corridor tile only one exit survives, so the target never matters there. Skipping the
  target calculation on such tiles is therefore equivalent, **except for frightened ghosts**,
  which call the PRNG on every tile entry, corridors included. The code already does this.
- **The PRNG advances per tile entry of a frightened ghost, not per frame.** The arcade's index is
  `index = (index * 5 + 1) & 0x1FFF`, reset to 0 at the start of the game and of each level
  (the Dossier adds: after each life lost). The output is the ROM byte at that index; only its two
  low bits are used: 00 right, 01 down, 10 left, 11 up. If that direction is invalid, the ghost
  tries the next one **clockwise** (right, down, left, up). Measured two-bit distribution over all
  8192 indices: up 16.3%, left 29.9%, right + down 53.7%. This is why frightened ghosts prefer
  turning left from their own point of view and drift to the bottom left.
- **Energizers reverse every ghost, frightened or not** (levels 17 and 19+). Already implemented.
- **Revived eyes return to scatter or chase** (the current wave), not always chase. Already
  implemented in A1.
- **No-up zones:** RGME describes them as tiles where scatter/chase ghosts do not update their
  direction at all. At the four arcade tiles that only removes the upward turn, so the current
  rule is equivalent. Frightened ghosts ignore them (F16).
- **The ROM is not used.** The copy on hand is an unlicensed download, so it is not unpacked,
  disassembled or shipped. Facts come from published analyses only. The speed masks stay
  placeholders (Decision 6), and the PRNG output table is a synthetic one matching the measured
  distribution (F17).

there are `Math.random`/`Date.now` calls inside the sim.

## Phase 5: Modern touches (optional, after fidelity)

- **Ruleset presets:** "Arcade" (all quirks, 60.606 Hz) vs "Modern" (quirks off, optional
  assist). Input buffering stays on in both (Decision 5). An optional "clear buffered direction
  on key release" setting gets closer to joystick behavior for players who want it.
- **Accessibility:** remappable keys, colorblind-safe frightened/flash palette, reduced-flash
  mode for the level-clear and energizer flashes.
- **Practice:** pattern recorder (save a replay as a "pattern", overlay it as a ghost trail),
  a per-level "first death" heatmap.
- **Input latency:** sample input at the start of each sim tick and render immediately after.
  Optionally, a latency readout in the debug HUD.

## Suggested order

1. **H1** (case fix) → H2–H6
2. **D1–D7** (determinism), with **T6** (scenario builder) alongside so tests can be written
3. **F1–F4** (speed and cornering, the biggest feel change). Rebaseline tests.
4. **A1 + F6–F13** (ghost state machine together with the house, Elroy and reversal fixes)
5. **A2 + F19–F22** (sequencer and feel)
6. F14–F18, F23–F24
7. **T4 → T5 → T7**, then T1–T3, T8–T9
8. A3–A7 as you touch each area. Then Phase 5.
9. **T11** (one dev panel, one pause owner) last, once the crucial features are polished.
