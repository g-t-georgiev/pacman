# Footage of the original, 2026-11-19

What three screen recordings of the original game show, measured frame by frame, and how we
will apply it. [`OPEN_ITEMS.md`](../OPEN_ITEMS.md) links here from each item this settles; once
a change is made, its row below says so and the manual describes the new behavior.

## The recordings

Three recordings of the original arcade game (Puck Man, Japan set 1) running in MAME, made
and played by a project member, at 30 frames per second. Only the recordings were used: nothing was taken from the game's program or data,
which this project never uses.

| Recording | What it shows                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 1         | Game starts and deaths on level 1, one with a fruit on the board. No sound.                                                     |
| 2         | Game starts and deaths on level 1. With sound.                                                                                  |
| 3         | The attract mode and its demo, a game start, a cleared level 1, the start of level 2, three deaths and a game over. With sound. |

### How it was measured

- **Times** come from the picture: when a part of the screen changes brightness (the "PLAYER
  ONE" text, the walls, the ghost house), or when the maze stops changing from one frame to
  the next (a freeze).
- **Positions** come from tracking each ghost's color in the ghost house, frame by frame.
- **Sounds** come from the loudness of the sound track and its spectrum. The recorder's sound
  runs about 0.2–0.3 s behind its picture, so sounds were used for pitch and length, never to
  time an event.
- **Precision:** one recorded frame is 1/30 s, about two of the game's frames. Lengths below
  are good to about ±0.05 s; where the recordings differ, both values are given.
- **Frames:** the game runs at about 60.6 frames per second, so 1 s is about 60 frames.

## How we will apply it

Every change to play (anything the golden replays record) needs `vp run golden:update`, which
bumps `RULES_VERSION` by one each time; the pre-commit hook won't let a play change through
without it. So the play changes are grouped into three commits (rules version 2 → 5), and the
two that only change the look or the sound come last, without touching the rules version.

| Step | What                                                                                                                                                           | Changes play | Why this order                                                                                                                         |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | **The ghost house:** reverse the start directions, house speed 40%.                                                                                            | Yes          | The directions are a mistake of ours, live since 0.2.0, and the smallest fix. The speed is in the same code and the same tests.        |
| 2    | **Round timing:** the PLAYER ONE step, the READY, death and level-clear lengths, the black screen before a level's READY, the death sound kept at about 1.5 s. | Yes          | The largest step: the round sequence, the renderer, the sound and their tests. Done as one commit so the lengths are re-recorded once. |
| 3    | **The fruit timer** runs during a death.                                                                                                                       | Yes          | Small and separate, in the fruit code.                                                                                                 |
| 4    | **The energizer blink**, steady during READY.                                                                                                                  | No           | Only the look; no replay changes.                                                                                                      |
| 5    | **The siren's stages.**                                                                                                                                        | No           | Only the sound.                                                                                                                        |

Each step also updates the manual (the rule's section and
[Estimates and open questions](../manual/03-arcade-rules.md#estimates-and-open-questions)),
ticks its items in `OPEN_ITEMS.md`, and marks its rows above as done.

### Notes for step 2

- Done as two new round phases, PLAYER_ONE and LEVEL_BLANK, rather than stretches of READY:
  agents, tests and the debug views see them by name.
- The death sound is tied to the animation's length today (`SoundEngine.ts`); it gets its own
  length so the longer animation doesn't stretch it.
- The tests that wait for play to start (e2e and agent scenarios) use these lengths, so they
  are checked here too.
